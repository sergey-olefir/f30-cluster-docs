# Brief: Twin Dial 0.1.1 — build everything that does not depend on the car

Audience: seven build agents, packages **B1 … B7**, working in parallel, each in its own git worktree. The design authority is `docs/twin-dial/SPEC-R3.md` (read it end to end first; §16 lists where it overrides older documents). The owner's instruction (2026-11-18): build everything that does not depend on the car now — **bake all the textures**, make the build — and do the car-dependent parts later. "After probe" items of the spec are **built and switched off** (a config key, a setting, or a page that shows its empty state) so that the car session only has to switch them on.

The lead merges, builds, versions and pushes. **You never push, never bump a version, never merge into `main`.**

## 0. The product

Twin Dial 0.1.1 (a build of `apps/twin_dial`; the version is set by the lead): the 06 dial look; live tabs, each selected tab filled in its colour; tab 1 pages including technical data (hideable); tab 2 messages in the centre (the bottom plate removed); tab 3 media (the certain-only page, the others built dark); tab 4 phone (idle page, the call card built dark); tab 5 navigation (the map window as an experiment, the fallback pages); the speed limit (a sign, a marker, the red strip); cruise and limiter built dark; the bottom row on connection 0 and in one line off tab 1; the Діагностика menu.

**Decided choices** (SPEC-R3 §0): look `80_look_06`; tabs 1–4 as the mockups; each tab its own colour; media from CarPlay; limit (a) + (b) + the strip red from the limit; cruise in the speedometer's lower opening; technical data hideable; no assistance page.

**Two readings still being drawn** (`docs/twin-dial/MOCKUP-SPEC-R3B.md`): the red strip (L1 / L2 / L3) and the cruise place (C1 / C2 / C3). Build **L1** and **C1** (the spec's readings) with the choice as a config key (`config.limit.strip` = "L1" | "L2" | "L3", `config.cruise.place` = "C1" | "C2"), so the owner's choice is a one-line change, not a rework.

**The numerals' shadow** (SD's measured model against K1's by-eye one) is also being drawn: bake SD's, behind one constant in `bake_face.py` (`SHADOW_MODEL`).

## 1. Rules for every package

- **Branch and worktree:** `git worktree add <main checkout>/.claude/worktrees/b3-<pkg> -b twin-b/<pkg> main`; symlink `reference` and `bake/work` (`git status --porcelain` must not list them). Commit often; the commit trailer is the one the harness gives you. **No push, no version bump, no change to `apps/f30_cluster` or `apps/driver_profiles`.**
- **f30_cluster must stay exactly as it is.** Before your last commit run all of `bench/test-*.js` one at a time (they rebuild `dist/`; headless; no Chrome or browser automation; no long-lived process you cannot stop yourself; ports 8080 and 8150 are the owner's — use 8600 + your number if a port is unavoidable). The counts on `main` today: bottom-row 254, cc-release 57, daynight 24, driver-profiles 105, fonts 34, mb-exp 46, native-ui 47, night 48, probes 25, scene-tex 54, strip-mask 40, twin-bake 35, twin-budget 75, twin-cc 149, twin-fonts 219, twin-layout 61, twin-pages 101, twin-probe 115, twin-sim 39, twin-trip 82. Tests of your own package are added; a test you must change on purpose (because the spec changed the thing it checks) is listed in your report with the reason.
- **No car** (no ssh). **Python:** `UV_CACHE_DIR=<main checkout>/bake/work/.uvcache uv run -q --no-project --with numpy --with pillow [--with fonttools] python -I <script>`. No home-directory path in a tracked file.
- **Not ours to ship.** No maker's name, logo, font or bitmap in a tracked file; the references (`reference/vc/`, git-ignored) are never an input to a bake and never copied; BMW's symbol bitmaps (`requestDefaultSymbols`) never baked, logged or committed; fonts are the OFL ones (Saira, Noto Sans); pictograms are our own. Never a VIN, key, token, coordinates, street names, media titles, contact names, numbers, or any personal data in a file, a test fixture taken from life, or a log line (numbers, enum names and lengths only; canary-string tests as `bench/test-twin-probe.js` does).
- **Platform rules** (learned the hard way): every `r` flag needs a non-zero getter id (`tools/signals/check_signals.py` must pass; a notifier-only field is `s`); every sampler2D bound; the KOMBI resets on too-big effect shaders (`tdial` ≤ 8 KB and `tdback` ≤ 6 KB after `compact()`; one look per shader source); `mediump` is fp16, use `highp` for lengths over 256 px; drop unused scene textures before making new ones; ≤ 8 layers per connection (3 connections), ≤ 6 MiB steady, ≤ 8 MiB at a layout switch (each image counted twice); no layer rectangle of ours intersects the gear-letter gap [1380, 660, 1460, 720]; the car runs **Node 8.16** (no `?.`, no `??`, no object spread, no optional catch binding, no `Object.fromEntries`, no `flat`); an OAP app that exits is counted as a crash — never an uncaught exception.
- **Safety (hard):** a BMW warning is never hidden unless our own text for that exact message is on screen in the same frame (SPEC-R3 §5.4). Keep-outs: BMW's belt group [497, 660, 688, 720], the gear-letter gap, the seven side-lamp holes, the hood line; the G20's black-box area is [1420, 320, 1611, 440].
- **Evidence:** write what you verified (test output, a picture diff against the mockups in `bake/work/twin-dial/mockup/r3/`) and what you did not. Nothing is proven on a car. A number that the spec does not give is a hypothesis you name.
- **Outputs:** code, baked files and tests on your branch; `docs/twin-dial/r3b/<PKG>-REPORT.md` (what was built, files, how to run, test results, open problems, every edit outside your files); a note for the others in `bake/work/twin-dial/r3b/pub/<PKG>/` with `READY` when something is usable. Finish with a short final message: branch, last commit, tests, what the lead must merge or decide.

## 2. The merge strategy (read before you touch `shared/hud.js`)

Seven packages edit overlapping files. To keep the merge small: **new code goes in new files** (`shared/twin_*.js`), and every edit of an existing shared file is a small hook block marked `// twin_dial:` (as round 2 did). The first writer's lines win; later packages add their own marked blocks and nothing else. Package ownership of existing files is in §3; a package that needs a change in a file it does not own sends it as a marked hunk and names it in its report.
