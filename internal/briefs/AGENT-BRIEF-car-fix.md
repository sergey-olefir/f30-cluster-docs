## 0. What the owner's car showed on 2026-11-18 (signal_probe 0.1.1; logs in `reference/car/2026-11-18-collect1/`, read-only, numbers only may leave it; the lead's later reads are summarised here)

- **Messages:** `KombiIF.statusActiveCCMessage` is dead on this car: `number` = **65535** all the time (also while a door message showed). **`Vehicle2.statusDisplayedCCMessage.statusNumberCheckControlMessageDisplay` is the real "shown now"**: door opened → ccList entry id 15 (WHITE) and displayed = **15** in the same ~ms; door closed → ccList back to id 0 at +2.9 s, displayed **0** about 0.7 s later. `KombiIF.statusMenuCCMessage` `id1` follows too (15, then 0). Displayed was also seen at 65535 right after an app start (= unknown), and at 184, 285, 926, 927 with other messages. `ccListRiskClass` and `CheckControlMaster.basicList` time out (not sent).
- **Speed limit:** `TrafficSignDisplayControl` — the field both apps were built on — **its provider never comes up**. The limit arrives as the **EVENT `de.bmw.dass.TrafficSignRecognition.TrafficSignRecognition`** (svc 13632, inst 1, ~2/s): **`presentClassLimitSpeed` × 5 = km/h** (class 8 when the front camera read a 40 sign, class 6 with a 30 sign, class 10 = 50 in town, also 12, 2, 1 seen); `nextClassLimitSpeed` 254 = none; `controlSLIWarning` 0/1 (likely the over-limit flag — hypothesis); `presentWithdrawalLimitSpeed` 1 always; `recognitionNoPassing` 0. The camera's own event `de.bmw.environmentalmodel.SignRecognitionFrontCamera.TrafficSignRecognitionFrontCamera` gives `[value=40 type=SPEED_LIMIT form=ROUND]` in km/h — a second witness. FASuS getters time out; CCP (map limit) is down while navigation runs through CarPlay. Event subscriptions are declared as `_broadcasts` (see `apps/signal_probe/app.json` and `fields.js` on main for the exact declaration and decoding).
- **Cruise / limiter:** `de.bmw.infotainment.displaydataserver.DisplayDataServer` field (probe tag `hud-data`; find it in `apps/signal_probe/fields.js`): **`cruise`** = set speed in km/h (61, 59, 40; 65535 = none), **`ldm`** = `LDM_SYM_DCC` (cruise) / `LDM_SYM_SLD` (limiter) / `LDM_SYM_NONE`, **`ldmColour`** `LDM_ACTIVE` / `LDM_OFF` — all filled with the HUD itself off. The FASuS-side `ldm-guidance` gives `func` `XCC_AKTIV` / `SLD_AKTIV` / none (its `setSpeed` is encoded, not km/h). Front vehicle (`front-vehicle`): `gapX` 57..1736, `speedX` ~1500 at equal speed, 4093 = none — scales are hypotheses, not for drawing yet.
- **Media:** arrives — `HmiMediaState` on `HMI_CID` (player metadata with line types, track progress, menu icon kind CARPLAY, main menu metadata), `TunerFmAmDab` station (band WB_FM), `MediaPlayer` on `CarPlayMedia` (item metadata, position, time, player state, device). Exact tags and fields: `apps/signal_probe/fields.js`.
- **Phone:** `ConnectivityAggregator.aggregatedCallState` arrives (DISCONNECTED, DIALING, ACTIVE seen); the S5 set's other fields: read the probe log the lead saved (`reference/car/2026-11-18-collect1/apps/signal_probe/`) for what arrived.
- **Navigation (route by CarPlay):** `Guidance.guidingProvider` = `CAR_PLAY`; **`nextDestinationInfo` arrives** (remaining distance raw/100 = km? e.g. 5700 with unit KM shown as 5.7; travel time s; ETA hour/minute) every few s; `isOnGuidableRoad` and `currentRoad` (text) arrive; **`conclusiveDart`, `nextIntersection`, lanes stay empty** with CarPlay (BMW navigation untested).
- **Trip / odometer / tab key:** already in 0.1.1 (B7): factors speed 0.1, cons 0.1, way 1; MileageSupreme metres; TRIP button = bit 0x40 of `IndicatorSteeringColumn.operationColumnStalks`.

## 1. Rules (as every round)

Worktree `<main checkout>/.claude/worktrees/cf-<n>` on branch `car-fix/<n>` from `twin-b/integrate`; symlink `reference`, `bake/work`. Read-only signals (`r` with a non-zero getter, `s` notifier-only, `_broadcasts` only for the named events above); `check_signals.py` passes for both apps. Never a setter, never a method with side effects. Privacy: titles, names, numbers, road names never logged (lengths and enums only). Node 8.16 syntax. **The safety rule is hard: a BMW warning is never hidden unless our own text for that exact message is on screen in the same frame.** Every suite green, run alone (`RUN_ALL_PORT` ≥ 8900, one runner at a time on the Mac — tell the lead before a full run); tests that fail when the feature is broken. f30_cluster's behaviour changes only where your package says so. Report `docs/car-fix/CF<n>-REPORT.md`, note in `bake/work/car-fix/pub/CF<n>/` with READY; finish with branch, last commit, tests, decisions.

## 2. Packages

### CF1 — messages: "shown now" from statusDisplayedCCMessage (Twin Dial and f30)
- **Twin Dial** (`shared/twin_cc.js`, the hud hooks): the "shown now" source becomes `ccDisplayed` (already declared and watched, `config.ccDisplayed`); `statusActiveCCMessage` stays declared but is ignored when it reads 65535 or never changes (config `ccActive.dead: true` on this car, or a rule: a value that is 65535 for the whole run is no witness). 65535 or no value on displayed = unknown → window open (as today). **D7 is satisfied** when displayed delivers a number that matches a ccList entry id — so after the first match our card covers BMW's panel. Displayed 0 with entries in the list = nothing shown by BMW → the panel may be covered and the entries are rows (stored). Displayed N with no entry → window open. Keep every other keep-open condition and the 150 ms rule. Rewrite the relevant `test-twin-cc.js` cases with the car's real sequences (door: list 15 + displayed 15 at once; close: list 0, displayed 0 at +0.7 s; start: displayed 65535, active 65535) and the per-frame audit.
- **f30_cluster**: the same rule in its `_ccListEval` path, as a config switch on in f30's `app.json` (`ccActive` source = displayed; the Діагностика "second witness" setting becomes the default-on path or is replaced — explain). This changes f30's shipped behaviour: test it with the same sequences in `test-bottom-row.js` / `test-cc-release.js` and the audit; the stuck-window case (65535 forever) must no longer keep the window open when displayed says 0 and the list is at rest.
- Do not change the release heuristics beyond what this needs; say what becomes obsolete.

### CF2 — the speed limit and cruise from the real sources (Twin Dial and f30)

Keep `TrafficSignDisplayControl` as a fallback source (it may exist on other cars).
- **Twin Dial**: B5's sign, marker and red strip (`shared/twin_limit.js`, `u_lim`) read from the new decoder; `config.limit.strip` unchanged (owner still choosing L1/L2/L3 — keep "L1" default). **Cruise / limiter on**: `config.cruise` = `{place: "C1"}` reading `DisplayDataServer` `cruise` / `ldm` / `ldmColour` (declare the field read-only), green when ACTIVE, grey otherwise, nothing for NONE or 65535; symbol cruise vs limiter from `ldm`; the green marker via `u_cru`.
